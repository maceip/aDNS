# Authenticate the CCF node before trusting the service identity

`tools/audit_ccf_node.py` retrieves only public quote data during an initially untrusted TLS handshake. It saves the actual peer certificate DER from that same connection, then invokes the separate Rust `audit_ccf_node` verifier against an independently selected policy. Only after successful native appraisal does it reconnect, require the exact audited peer certificate before sending HTTP, and retrieve `/node/network`. The service certificate returned through that authenticated node channel can then be used for governance and ordinary service TLS. No member proposal, control token or private key is sent during untrusted bootstrap. Both bootstrap requests have an absolute 15-second transport deadline beginning before connection setup; a timer shuts down the socket so trickled response headers or bodies cannot restart the deadline. Read/connect operations also have a 10-second timeout and responses are capped at 1 MiB. Hostnames use the operating system resolver; the helper checks its absolute deadline again before transmitting HTTP after resolution/connect completes. Five transport tests cover changed-peer rejection before any HTTP bytes, bounded responses, a stalled TLS handshake, rejection of trickled headers/body, and no service-certificate fetch after failed native appraisal.

```sh
cargo build -p adns-attest --example audit_ccf_node
python3 tools/audit_ccf_node.py --url https://NODE:8000 --policy independently-approved-node-policy.json --output .validation/azure/node-bootstrap
```

Native ACI control preparation requires `python3 tools/prepare_aci_control.py CONTROL_DIR --constitution-sha256 PACKAGED_CONSTITUTION_SHA256 --native-snp`. This adds the CCF 7.0.15 SNP security policy, UVM endorsement and cached AMD certificate paths under `$UVM_SECURITY_CONTEXT_DIR`, plus Azure and AMD HTTPS collateral fallbacks. The actual first native deployment without these fields failed during node creation; this is checked by the deployment helpers before future ACI submission. The generic example and local Virtual runner intentionally omit these native paths.

The node policy uses the existing `AppraisalPolicy` schema but is independently selected for the CCF ACI group, including its exact approved CCE policy digest, platform measurement, minimum TCB and Microsoft UVM identity. Explicit approved-release endorsement semantics must be selected when appropriate. Observed quote fields never automatically populate an allowlist.

The audit verifies current pinned AMD chains, authentic report signature, VMPL0/debug/migration requirements, all TCB floors, full64-byte DER SPKI binding, exact policy measurement/CCE digest, Microsoft UVM chain/signature/identity/feed/SVN, node ID and peer-certificate lifetime. CCF P384 and P256 node keys are supported. Virtual profiles and malformed/ambiguous encodings fail. Expiry is bounded by the node certificate, current AMD endorsements, governed policy and appraisal interval.

This is a distinct `AuditedNodeQuote` API tagged `ccf-node-tls-bootstrap-only`; it cannot construct the service's `VerifiedAppraisal` and is never used for registration admission. It establishes the approved node identity and its authenticated service-certificate response, not CCF global commitment, member intent, or application request authorization. Fresh native node success requires actual Azure evidence; native historical fixtures still fail their unrelated key binding and cannot be relabeled as a node success.

Pinned primary source: CCF7.0.15 [node_state.h](https://github.com/microsoft/CCF/blob/ccf-7.0.15/src/node/node_state.h#L1142) computes SHA256 of `node_sign_kp->public_key_der()`. Its [quote verifier](https://github.com/microsoft/CCF/blob/ccf-7.0.15/src/node/quote.cpp#L126) compares that digest, [node endpoint](https://github.com/microsoft/CCF/blob/ccf-7.0.15/src/node/rpc/node_frontend.h#L756) returns the native report/endorsements, and [JSON byte serialization](https://github.com/microsoft/CCF/blob/ccf-7.0.15/include/ccf/ds/json.h#L123) emits standard base64. The Rust audit additionally checks every zero-padding byte.

The native preparation helper also permits exact `/node/state` beside `/app/internal/.*` on the internal loopback interface. The packaged supervisor authenticates this readiness response before it launches autonomous maintenance and transfer relay. CCF 7.0.15 returns HTTP503 when an interface ACL denies a route, so omitting this exact readiness exception prevents the driver from starting. Broader node-route wildcards are rejected by native preflight.
