# Bounded authority and transport tracing

`host_driver.py` calls `telemetry.initialize("agentdns-driver", receive_socket=AGENTDNS_TRACE_SOCKET)`. Its own spans use `service.name=agentdns-driver` (or the explicit `OTEL_SERVICE_NAME` override) and `agentdns.component=driver`. Native C++/Rust spans received on the local socket always use `service.name=agentdns-authority` and `agentdns.component=authority`. Both include `service.version=0.1.0`. `OTEL_RESOURCE_ATTRIBUTES` accepts only bounded `deployment.environment`, `service.namespace`, and `service.instance.id`; unknown attributes are rejected. `OTEL_SDK_DISABLED=true` disables both. Missing or invalid diagnostics configuration is reported once without its contents and does not disable authority transport.

The [official Python SDK and HTTP/protobuf exporter](https://opentelemetry.io/docs/languages/python/exporters/) are pinned with their resolved dependencies in [requirements-otel.txt](requirements-otel.txt). Version [1.44.0](https://pypi.org/project/opentelemetry-sdk/1.44.0/) supports Python 3.10 and newer. The standard `BatchSpanProcessor` queues at most 2,048 spans, batches at most 256, and wakes every second. Queue saturation drops diagnostics rather than blocking application work. Shutdown waits at most 1.5 seconds for the processor, then stops further exports. This timeout uses the pinned SDK's internal `BatchProcessor` method because its public span-processor wrapper has no shutdown-timeout argument; the regression suite exercises that boundary.

The C++ producer makes at most 64 lock-free queue attempts and performs no socket I/O in the request or consensus callback. Its background exporter gives each complete request batch one 50 ms retry budget for a full Unix datagram queue or an interrupted send, sleeping 1 ms between attempts. A failed send stops the remaining descendants and increments the dropped-batch counter; an already delivered prefix can remain, so transport is best effort. Historical transaction contexts enter the 256-entry link cache only after the entire batch was sent. With at most 64 batches being drained and another 64 queued, shutdown has at most approximately 6.4 seconds of accumulated retry budgets, plus serialization and scheduling overhead. The permanently stalled-consumer regression observed 6.307 seconds for shutdown; this is a measured fixture result, not a universal wall-clock guarantee.

The default export target is `http://127.0.0.1:4318/v1/traces`. `OTEL_EXPORTER_OTLP_ENDPOINT` supplies an origin or the existing gateway prefix `/_ops/telemetry/<source>`; `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` supplies the exact URL ending in `/v1/traces`. Other path prefixes, encoded path separators, queries and fragments remain unsupported. Only protocol `http/protobuf` is supported; the traces-specific protocol setting takes precedence over the general setting. Plain HTTP is restricted to loopback and cannot carry configured headers or custom trust. HTTPS always validates the hostname and either system trust or the public CA in `OTEL_EXPORTER_OTLP_CERTIFICATE` (`_TRACES_CERTIFICATE` takes precedence). A configured CA is read once from a bounded absolute regular file; false/empty values never disable TLS verification.

`OTEL_EXPORTER_OTLP_HEADERS` and the overriding `OTEL_EXPORTER_OTLP_TRACES_HEADERS` accept SDK-style comma-separated, percent-decoded key/value pairs. At most 16 pairs and 4 KiB of encoded/decoded data are accepted. Names/values are bounded; CRLF, controls and transport overrides such as Host, Content-Length, Cookie or Transfer-Encoding are rejected. Configured authentication headers are sent only to the exact HTTPS collector endpoint and never added to trace attributes or logs. Proxies, redirects, cookies and client certificates are unsupported. The exporter sends standard OTLP protobuf through a bounded direct transport; response text is replaced with a fixed sanitized diagnostic. Each network operation has a one-second absolute socket deadline across TLS, headers and a response body capped at 64 KiB. DNS resolution for an explicitly configured hostname remains OS-managed; the default numeric loopback path avoids that boundary. Shutdown and producer queues remain bounded even if a resolver stalls.

The Unix datagram receiver accepts at most 60,000 bytes and a strict version-1 schema:

```json
{"v":1,"trace_id":"0123456789abcdef0123456789abcdef","span_id":"0123456789abcdef","parent_span_id":null,"name":"ccf.request","kind":"server","start_unix_nanos":1789290000000000000,"end_unix_nanos":1789290000001000000,"status":"ok","attributes":{"http.route":"/service/register","http.request.method":"POST","ccf.transaction_id":"2.41"},"links":[]}
```

IDs must be nonzero lowercase hexadecimal; parents stay in the same trace. Kinds and statuses are fixed enums. Timestamps are positive signed-64-bit nanoseconds with a duration of at most one hour. At most 16 explicitly typed public attributes and eight ID-only links are accepted. Duplicate/unknown fields, unknown operations, invalid enums, arbitrary errors, bodies, credentials and unbounded values are rejected. The operation and attribute allowlists are in `telemetry.py`. The socket is mode 0600 in a directory that cannot be written by group/others; an existing endpoint is never silently replaced. Imported spans retain their original IDs, parent, timestamps and links through SDK `ReadableSpan` objects. Their times and status describe the emitting execution; only explicitly recorded CCF commit outcomes establish that the application reported a commit.

The supervisor creates a private mode-0700 socket directory and passes the fixed image-owned Python dependency path only to the driver. After reaping the exact old driver, it may remove only its configured stale socket: it verifies the original parent identity, owner and mode, socket type/owner, and a failed datagram connection with `ECONNREFUSED`. An active listener, replacement inode, symlink, regular file or uncertain condition is preserved. This permits telemetry recovery after a killed driver or service-identity replacement without removing another live listener.

Driver HTTP client spans inject only W3C `traceparent`; no baggage or trace state is forwarded. `driver.ccf.commit_wait` measures the client's HTTP/commit wait, including network overhead, not an isolated Raft duration. The existing commitment gate remains authoritative: a response is marked committed only after its headers and expected binary/JSON structure pass. Executor work captures and attaches its actual Python context explicitly.

A 256-entry, ten-minute cache provides asynchronous links when actual context is available. NOTIFY's DNS packet contains no serial, so the driver learns it only from the committed acceptance response's `secondary.last_notified_serial`. AXFR links by the actual transferred first SOA serial and records completion after sending the unchanged frames. SOA observation links are recorded only after CCF verifies the response and confirms its transaction. Later native signing can link to the latest authenticated observation; this is an explicit asynchronous link, not parentage or a claim that the new signing execution committed. Cache eviction, ordering races or missing metadata omit a link. No DNS/TSIG packet is modified to carry tracing context, and diagnostic parsing never replaces authoritative DNS or TSIG validation.

Run focused tests with `python3 -m unittest ccf.test_host_driver ccf.test_telemetry -v` after installing the pinned requirements. Tests use actual ephemeral local HTTP/TLS/Unix sockets and decode real OTLP protobuf, exercise resource/ID preservation, malformed inputs, secret exclusion, queue saturation, finite shutdown, slow headers, context propagation and the NOTIFY→AXFR→SOA→refresh link sequence. The link test uses a fake committed CCF gate and makes no TSIG or hardware claim. Existing native deployment evidence predates this tracing change; a rebuilt, instrumented deployment needs its own evidence.

The [real CCF trace proof](../docs/evidence/otel-ccf-live-20260913/README.md) runs the existing three-node quorum and disk recovery scenarios through the SDK and a bounded local OTLP/protobuf sink. It checks actual caller parentage, committed rejection status, signing/receipt children, historical transaction links and absence of business spans from requests lost with the killed leader. Its optional collector forwarding is independent of the local assertions.

For a new native deployment, `tools/build_aci_template.py` accepts six optional settings together: `--otel-endpoint` (an HTTPS origin or the existing scoped gateway prefix; omitted port means 443), `--otel-public-ca`, `--otel-secret-file`, `--otel-deployment-environment`, `--otel-service-namespace`, and `--otel-service-instance`. The owner-only secret JSON must contain matching `endpoint`, `header_name`, `header_value` and `OTEL_EXPORTER_OTLP_HEADERS` fields for one canonical Basic authorization header or a Bearer token of 32–256 base64url characters. The hosting monitor requires a separate declared trace-only source and matching token hash; do not reuse the worker status publisher credential. The tool emits only a secure parameter reference in the public template, following [ACI secure environment-variable support](https://learn.microsoft.com/en-us/azure/container-instances/container-instances-environment-variables#secure-values). The actual header remains in the mode-0600 parameter file. A separate read-only public CA volume preserves the CCF bootstrap manifest; its content hash is recorded in the public summary. The generated CCE policy constrains the CA mount/path, while the reviewed template identifies its bytes.

Apply the emitted public `otel-env-rules.json` to the primary's confcom policy after generation: four exact nonsecret settings and one bounded `re2` pattern for a bounded percent-encoded Basic or Bearer header. Never embed the actual header value in that policy. `tools/check_aci_template.py` validates these rules, rejects broad extra environment patterns, and checks HTTPS, HTTP/protobuf, the three permitted resource labels, the secure parameter and the read-only CA mount. Omitting all six options preserves explicit `OTEL_SDK_DISABLED=true`. These helpers remain initial validation tooling, not a replacement for the reviewed Join/Recover lifecycle. Enabling export on an existing authority requires a reviewed image/CCE/configuration and fresh native appraisal; generator tests and synthetic trace transport do not establish native activation or transaction commitment. Trace export does not identify the origin of periodic TCP probes.
