# Real CCF and Python SDK trace proof

The existing real three-node quorum and disk recovery scenarios passed on the instrumented ELF pinned in `provenance.json`. This is local Virtual CCF consensus evidence, not native Azure hardware evidence. No standalone C++ fixture replaced either scenario.

Quorum produced 184 actual OTLP spans from 175 HTTP attempts, with 34 exact committed request-parent checks, 13 waits longer than one second, and four requests lost with the killed leader that exported no business spans. Disk recovery produced 140 spans from 86 attempts, with 24 committed request-parent checks. Both scenarios verified the same signed envelope failing under revoked governance, succeeding after reauthorization, and returning its historical committed result. A globally committed HTTP403 remains an error trace with a failed grant-check span. Genuine DNSSEC signing, receipt creation, and ID-only historical transaction links are present.

All 324 accepted native datagrams reached 29 actual SDK HTTP/protobuf batches. The receiver rejected no datagrams, and checked CCF request roots reported zero dropped batches. Exact protobuf bytes were then forwarded successfully to the local Collector. Collector/Tempo retrieval is independently recorded elsewhere; successful forwarding alone does not claim successful backend retrieval. No driver-to-secondary asynchronous link or native hardware trace is claimed by this authority-only run.

The 16 supervisor regressions also passed on Linux, including actual killed-child socket recovery, active-listener preservation, private-directory/type/identity checks, fixed driver-only dependency paths and credential isolation, and bounded TLS/header/body behavior.

Two earlier attempts remain separate in private validation storage. Attempt1 completed its quorum scenario but the verifier wrongly required a parent for an intentionally untraced provisioning request root; that assertion was corrected. Attempt2 exposed real nonblocking Unix-datagram queue loss, including incomplete committed traces. The background exporter was corrected to use a bounded50ms retry budget per batch, and this fresh complete run passed without weakening completeness checks. The initial Requests warning was traced to the test tmpfs lacking executable mappings for a pinned wheel; this run explicitly enabled exec on its disposable dependency tmpfs. Runtime-image dependencies live under `/opt` and were not affected.

The source allowlist and hashes matched before/after execution; the disposable container was removed. Public exports contain only the explicit source/proof files, sanitized request metadata, and decoded/encoded trace data validated against the production allowlists. Member keys, TSIG bodies, full ledgers, HTTP bodies and complete CCF node logs remain excluded.

To reproduce in a CCF toolchain containing `/build/agentdns`, install `source/ccf/requirements-otel.txt`, make its Python packages importable, and run `python3 /src/ccf/tests/live_telemetry.py --output /out/new-proof`. This runs both real scenarios and uses a bounded local OTLP sink. The optional `--collector-url http://127.0.0.1:4318/v1/traces` forwards verified batches to a local collector. The exact tested Docker invocation and isolated runner are included.
